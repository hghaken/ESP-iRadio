# Schematic and board generators

The Rev B schematic (`../esp-iradio.kicad_sch` + `../power_usb.kicad_sch`) and the first layout
(`../esp-iradio.kicad_pcb`) are generated by these scripts, so a change is made here and the files
are written again; the scripts check what they can as they go.

## Schematic

| File | Purpose |
|---|---|
| `schgen.py` | small KiCad 9 schematic writer: symbols from the project/KiCad libraries, wires with automatic junctions, power symbols, local and global labels, a sheet symbol, sub-sheet instance paths; test pads and holes are kept out of the BOM |
| `fieldcheck.py` | warns about reference/value texts that overlap each other, cross a wire or sit on a symbol |
| `gen_radio.py` | sheet 1 (root): ESP32-WROVER-IE, display module sockets, microSD, encoder, audio |
| `gen_power.py` | sheet 2: USB-C, CH340C + auto-reset, BQ24074 charger, cell protection, regulators, on/off switch, recovery pads |
| `intcheck.py` | checks an exported netlist against `../../07-integrated-board.md`: groups of pins that must share a net, nets that must stay apart (VBUS/VIN, VSYS/VBAT, VSYS/+3V3, GND/BATN; local nets by their full sheet path), parts that must not come back. It does not check values, polarity or footprints |

Run from this folder (Python 3, no packages needed):

```
python gen_power.py ..
python gen_radio.py ..
kicad-cli sch erc --severity-all -o erc.rpt ../esp-iradio.kicad_sch
kicad-cli sch export netlist --format kicadsexpr -o board.net ../esp-iradio.kicad_sch
python intcheck.py board.net
```

Expected: ERC 1 warning (the MAX98357A exposed pad, pin type unspecified, on GND) and `OK` from
`intcheck.py`. Close the schematic in KiCad first.

## Board (Rev C, 122 x 76 mm)

| File | Purpose |
|---|---|
| `pcbrules.py` | design rules and net classes into `../esp-iradio.kicad_pro` (JLCPCB 4-layer: 0.2/0.15 mm default, Power 0.5 mm, Supply 0.3 mm, vias 0.55/0.3, edge 0.3 mm), plus `../esp-iradio.kicad_dru` (one custom rule: the display module's standoff holes may touch its sockets) |
| `placement.py` | the floor plan: position and rotation of every part (comments explain the zones) |
| `mkpcb.py` | builds the board from the netlist: empty file, 4 layers (In1.Cu = GND plane, layer type power), outline from `placement.W/H` (122 x 76 mm), outlines of the display module (PCB, glass, active area) on User.Drawings, footprints with fields and schematic links, nets, placement, GND plane, 0.6 mm track/via keep-out along the edges. `--check` only reports overlaps (courtyard plus pads) |
| `route.py` | Specctra DSN export, Freerouting, SES import, GND pours on F.Cu/B.Cu (SMD pads solid, THT pads thermal), zone fill. `--keep` routes only what is still open |
| `stitch.py` | GND stitching vias on a 2.5 mm grid where the outer pours have room, a via (or a short track) for every pour island |
| `silk.py` | silkscreen: references only on connectors, ICs, switches, LEDs and transistors; fields hidden; polarity and function markings (+/-, CELL/SPK, 5V, ON/OFF, RCA L/R, recovery pad names), title at `placement.TITLE` |
| `touchup.py` | hand edits on the routed board (review round 5): fifth BQ24074 thermal via, vias in the WROVER ground land, charge-LED labels "C"/"P"; no hole below 0.3 mm (the QFN thermal-via pads get a 0.3 mm drill, its vias are 0.5/0.3 and older smaller ones are resized); checks every via against other-net copper and holes; idempotent |
| `bridge.py` | joins a pad the router left unconnected: `bridge.py REF PAD`, straight/L track on F.Cu or a stub + new via + B.Cu/In2.Cu to a via of the net, every candidate checked against other-net copper and holes (not needed on the current board) |
| `jlcfab.py` | JLCPCB order files in `../jlcpcb/`: BOM (LCSC field, else the basic part for plain R/C from its table), CPL (pad centre, Y up, the JLCPCB Tools plugin's rotation corrections for KiCad footprints, none for the EasyEDA `lcsc` ones) and a Gerber + drill zip made with kicad-cli |
| `fp3d.py` | project copies of the KiCad USB-C (HRO TYPE-C-31-M-12) and EC11E encoder footprints with the EasyEDA 3D models aligned on the pads (KiCad's own 3D folders for them are missing on the owner's PC), J3's socket footprint with the display module model, and the PJ-320D model made solid; writes `../lib/esp-iradio.pretty/` |
| `display3d.py` | simple VRML model of the HS20S010B module on its sockets (`../lib/esp-iradio.3dshapes/`) |
| `relink.py` | points every footprint at its schematic symbol again (path from the netlist) without touching the layout |
| `fplib.py`, `netparse.py` | footprint loading and netlist reading for the board scripts |

The board scripts run with KiCad's own Python. Freerouting 1.9.0 needs Java (17 or newer); on the
owner's PC both are portable in `C:\Users\Admin\tools\` (`jdk-21.0.12.1+1-jre`,
`freerouting-1.9.0.jar`; override with the environment variables `JAVA` and `FREEROUTING`).
Freerouting 2.x jars need Java 25; the 2.5.0 native CLI crashed while routing.

```
set KP="C:\Program Files\KiCad\9.0\bin\python.exe"
python pcbrules.py
%KP% mkpcb.py board.net --check
%KP% mkpcb.py board.net
%KP% route.py 100
%KP% route.py 40 --keep
%KP% route.py 40 --keep
%KP% stitch.py
%KP% silk.py
%KP% touchup.py
%KP% jlcfab.py
kicad-cli pcb drc --schematic-parity --severity-all -o drc.rpt ../esp-iradio.kicad_pcb
```

Expected: 0 errors, 0 unconnected items, 0 schematic parity issues; ~40 warnings, all silkscreen
(the footprints' own outlines, texts near the edge). Freerouting does not give the
same result twice: when a run leaves something open, run `route.py 40 --keep` again or move the
part in `placement.py`. Close the board in KiCad first.

**Once the layout is edited by hand in KiCad, stop regenerating**: `mkpcb.py` starts from an empty
board (and the schematic scripts overwrite both sheets). From then on, change the schematic in
KiCad and use "Update PCB from Schematic".
